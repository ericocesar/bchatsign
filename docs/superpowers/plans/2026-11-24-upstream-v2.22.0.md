> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Trazer o release v2.22.0 (e o patch v2.21.1) do upstream Documenso para o `develop` do fork bchatsign, preservando todas as personalizações do fork (selagem ICP-Brasil/VALIDAR-ITI, certificado por página, geolocalização, pt-BR, enums gerados, formatação biome).

**Architecture:** O fork não faz merge direto do upstream. Um espelho normalizado (`vendor/upstream-bchatsign`, tags `mirror/*`) aplica rename `documenso→bchatsign`, troca de `@documenso/skia-canvas` por `skia-canvas` e o biome do fork. O merge acontece contra esse espelho, então os conflitos ficam restritos a divergências reais de conteúdo. Tudo roda em um worktree separado; `develop` só é avançado no final.

**Tech Stack:** git worktree + mirror tags, bash (`scripts/upstream-sync/`), npm 11 / Node 24 (`nvm use 24.19.0`), Prisma 6, biome 2.4.8, Playwright, Lingui.

    if (!address) {
      return [];
    }

    if (typeof address === 'string') {
      return [{ email: address }];
    }

    if (Array.isArray(address)) {
      return address.flatMap((item) => this.toMailChannelsAddresses(item));
    }

      return this.toMailChannelsAddresses(address.group);
    }

    if (!address.address) {
      return [];
    }

    return [
      {
        email: address.address,
        name: address.name,
      },
    ];
  }

## Notas de risco

1. **`seal-document.handler.ts` é o ponto de falha mais provável.** Ele concentra as duas trilhas de mudança (upstream reescreveu a inserção de campos; o fork adicionou certificado/evidência). Valide com documento real (Task 10, Step 5), não só com `tsc`.
2. **Migrations de e-mail em minúsculas alteram dados.** Antes de `prisma:migrate-deploy` em produção, conte duplicatas case-insensitive:
   ```sql
   SELECT lower(email), count(*) FROM "User" GROUP BY 1 HAVING count(*) > 1;
   SELECT lower(email), count(*) FROM "Recipient" GROUP BY 1 HAVING count(*) > 1;
   ```
   Duplicatas em `User` precisam ser mescladas à mão antes do deploy.
3. **`package-lock.json` com `min-release-age = 7`.** Versões recentes do upstream (ex.: `@hono/node-server 1.19.19`, 13 dias; `react-email 6.11.11`, 14 dias) passam. Se aparecer algo com <7 dias, o npm recusa e nomeia o pacote — use a versão anterior e documente.
4. **O bug do `build-mirror.sh` com caminho relativo** é silencioso. Se alguém regerar o espelho, verifique a formatação comparando um arquivo conhecido:
   ```bash
   git show mirror/v2.22.0:apps/remix/app/root.tsx | head -3
   ```
   Deve começar com `import` agrupado, sem linhas em branco extras entre grupos de import (é o que o biome do fork produz).
5. **`@documenso/nodemailer-resend` 5.0.0 vs nodemailer 10** é uma dívida técnica pré-existente que este release não resolve. Se o `tsc` de `packages/email` piorar por causa disso, é a hora de subir para 6.0.1.
