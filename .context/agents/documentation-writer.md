## Mission

Keep BchatSign's documentation accurate, current, and discoverable. The public docs live in `apps/docs/` (MDX); internal docs live in `.context/docs/`; READMEs and runbooks live next to the code.

## When to Use

- Adding or updating public docs in `apps/docs/src/app/docs/[[...slug]]`.
- Updating internal architecture or workflow docs in `.context/docs/`.
- Writing a feature announcement, runbook, or onboarding guide.
- Translating documentation across the supported locales (en, pt-BR, es, fr, de, it, ja, ko, nl, pl, zh).
- Producing a release note or a changelog entry.

## Workflow

1. **Identify the audience** — public user, internal developer, support engineer, or admin. Pick the right surface (`apps/docs`, `.context/docs`, or a runbook in the team wiki).
2. **Source of truth** — read the code first. The semantic snapshot and the relevant service files are the contract; never infer behaviour from the previous version of the docs.
3. **Structure**:
   - **Public docs** — Hero → Quickstart → Concepts → Tasks → Reference → FAQ.
   - **Internal docs** — Overview → Architecture → Data flow → Glossary → Conventions.
   - **Runbooks** — Symptom → Cause → Detection → Mitigation → Rollback.
4. **Write the doc**:
   - One sentence per paragraph in the lead.
   - Use H2/H3 hierarchy; no orphan H1s.
   - Code blocks for commands; flags inline.
   - Use callouts for gotchas, prereqs, and security notes.
5. **Cross-reference** — link to other docs and to the source file with `path:line` so future readers can verify.
6. **Localize** when UI strings are involved — entries must exist in every locale under `packages/lib/translations/`.
7. **Validate** — `pnpm dev` for the docs site; spot-check links and search; the `documentation` skill enforces structure.

## Project Conventions

- **MDX first** for the public docs site (`apps/docs`); use the `apps/docs/src/components/mdx` primitives for callouts, code blocks, and tabs.
- **Search** — every page emits a structured frontmatter consumed by `apps/docs/src/app/api/search`. Add a short description and tags.
- **OG images** — generated by `apps/docs/src/app/og/docs/[...slug]`. The doc slug is the source of truth.
- **LLM-friendly** — `apps/docs/src/app/llms.txt` and `llms-full.txt` aggregate docs for AI assistants. They regenerate from the MDX source.
- **Internal docs** live in `.context/docs/` and are referenced by `context({ action: "getMap" })`. The semantic snapshot is the canonical architecture summary.
- **Translations** are code-side; documentation is English-only unless explicitly translated.
- **Runbooks** are co-located with the responsible package (`packages/<pkg>/RUNBOOK.md`) when narrow, or under `docs/runbooks/` when cross-cutting.
- **Date format** in examples: `DD/MM/YYYY HH:mm` for `pt-BR`; use the `formatDate` helper in code blocks.
- **Conventional Commits** — the `commit-message` skill enforces it for documentation PRs.

## Output Format

- **Doc pages**: MDX with frontmatter, sections, callouts, and cross-links.
- **Internal docs**: markdown in `.context/docs/`, status updated to `filled`.
- **Runbooks**: short, actionable, with detection and rollback steps.
- **Translations**: entries in every locale when UI strings are involved.
- **Sensors**: which `.context/harness/sensors.json` sensors gate the doc change (e.g. `i18n-keys-present`, `docs-build`).
